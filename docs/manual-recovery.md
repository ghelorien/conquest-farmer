# Manual recovery and externally added stock

Use **Recheck** on the affected farmer or merchant to inspect a recovery hold.
If you handled the incident yourself, use **Override & resume** and confirm the
specific incident shown. This is a one-time decision for that profile, not a
permanent switch that disables recovery checks.

An override preserves the original evidence and records an operator decision.
It does not count as a verified sale, delivery, payment, or exchange. The app
must inspect current memory and plan new work rather than replay the uncertain
action. Stop, manual input ownership, unavailable memory, and an active trade
can still prevent immediate movement; the status explains the remaining wait.

You can complete trades from other characters yourself. Added stock remains
subject to the ordinary protection, pricing, and capacity rules. Automation
does not accept unfamiliar trade requests. Changes involving an unresolved
automated transaction require reconciliation or your explicit override.

Meteor departure attempts are recorded immediately before dialog submission.
An interrupted approach therefore does not by itself imply an uncertain fare.
An interruption after submission can still require a recheck or override.

Runtime audit records remain local with the existing journals and credentials.
An override is not evidence that an item was lost or transferred successfully.
